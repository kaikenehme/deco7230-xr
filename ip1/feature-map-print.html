Architecture rule (concept §8): surfaces never know samples or menus exist. Surface is a state machine; HoldUpPreviewer is the sole coupling point between a held sample and a surface; the menu commits through the same Surface preview/commit API the hold-up loop uses. One write path — that's why menu and hold-up can be compared fairly (assumption A3).

The core loop — mark · pull · hold · tune · commit

FeatureImplementationHow it works
Mark (keep/change)Scripts/Runtime/MarkTool.cs · Surface.csBrushing a controller across a surface while holding grip toggles Keep/Change. Grip gate + sweep-speed threshold stop accidental toggles (open Q3); per-surface debounce stops double fires.
Pull (sample source)Scripts/Runtime/SamplePuller.cs · Sample.csTouch a Keep surface + trigger → spawns a sample already held by that controller. Pulling from a Change surface is refused — only kept things are sources; that is the concept (§9).
Hold-up previewScripts/Runtime/HoldUpPreviewer.csWhile held: nearest Change surface in range previews the sample colour; leaving range always reverts (a preview must never stick, §9). Sole coupling point between Sample and Surface.
Tune (twist)Scripts/Runtime/HarmonyTuner.cs · HarmonyPalette.csController roll (relative to grab pose) indexes a 7-option palette generated from the pulled colour, ordered safe→bold: analogous pair, tonal pale/deep, triadic pair, complementary.
Commit / discardHoldUpPreviewer.cs · Surface.csRelease in range commits the previewed look to the surface; release mid-air discards the sample. Surface stores committed vs previewed colour AND material separately.

Diegetic controls — no floating menus

FeatureImplementationHow it works
Light (lamp)Scripts/Runtime/LampController.csTouching the lamp cycles Warm → Cool → Daylight, relighting the room. Three states, not on/off: "does this green survive a warm bulb at 9pm?" (§7).
Compare (schemes)Scripts/Runtime/SchemeCycler.cs · SchemeManager.csPrimary button saves the current scheme (max 3, colour+material snapshot per surface); secondary cycles saved schemes. Physical controller buttons — the no-menus rule holds.

Controller menu (added 25 Aug for the A3 comparison)

FeatureImplementationHow it works
Open / targetScripts/Runtime/MenuSelectRelay.cs · MenuTarget.cs · RayUtil.csRight trigger fires a physics ray → anything with MenuTarget opens the menu for it. Ray skips the rig's own colliders and never treats the menu panel as a wall (tag MenuPanel). Trigger on nothing closes.

Furniture & locomotion

FeatureImplementationHow it works
Move (grip-grab)Scripts/Runtime/FurnitureSlot.csEvery furniture piece is a slot: stable GameObject holds pose, box collider, XRGrabInteractable (kinematic, no throw); the visual is a swappable child. Grip grabs, drag with the ray; release snaps flat to floor, clamped inside the room. Discoverability = data-sheet row 16.
Swap / add / removeFurnitureSlot.Swap() / .Spawn() / .Remove()Menu's furniture tab spawns a new slot at the aimed floor point or swaps the targeted slot's visual; collider auto-fits renderer bounds; sofa is a slot too (kept = also a sample source).
TeleportEditor/SceneBuilder.cs · RoomSpec.csFloor is a TeleportationArea on interaction layer 31 (reserved in RoomSpec.TeleportLayer) so teleport rays and select rays never collide. Point at floor + trigger.
Aim feedbackScripts/Runtime/RayFeedback.cs · RayUtil.cs4 cm reticle oriented to the hit normal (safe up-vector — the Invalid-AABB fix) + emission glow on whatever the ray points at. Pure per-frame state machine.

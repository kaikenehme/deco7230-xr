# Code walkthrough — IP2a (for questions in the studio)

Where each feature lives, and what changed since IP1. Line numbers are as of `1860a94` (24 Sep); if a line has moved, search for the method name.

**Where the files are** (Unity's Project panel, or Finder under `ip2a/RenovationPreviewer/`): `Assets/Scripts/Runtime/` = the app's code · `Assets/Editor/` = scripts that build the scene, rooms and catalogue · `Assets/Scripts/Tests/` and `Assets/Scripts/PlayModeTests/` = tests. IP1 as tested = git tag `ip1-submitted`.

## The 30-second answer

- **The scene is generated by code, not built by hand.** `Editor/SceneBuilder.cs` `Build()` (line 29) creates the room, window, lamp, clock, preset frames, the XR rig and wires every script. `Room.unity` is its output; I never edit it directly. Same for the three rooms (`Editor/PresetAuthoring.cs`) and the furniture/paint/material catalogue (`Editor/CatalogueImporter.cs`, CC0 assets from Poly Haven and ambientCG, Dulux colour names).
- **Surfaces and samples never know about each other** (concept spec §8). `Surface` holds a wall's state and colour; `Sample` holds a pulled colour; `HoldUpPreviewer` is the only script that connects them. That keeps the hold-up loop and the menu independent: both just call `Surface.Preview` / `Commit`.
- **No floating menus for the core loop.** Lamp, clock and preset frames are objects you touch in the room. The controller menu is the one panel, and it exists for the A3 comparison (constrained hold-up vs open catalogue).
- **Tested:** 33 test files. EditMode 169 + PlayMode 27, all passing. PlayMode tests load the real generated scene and check the wiring (`Scripts/PlayModeTests/SceneWiringTests.cs`), including a furniture-layout check for every preset room.
- **Size:** about 3,200 lines of runtime C# across 43 scripts.

## The core loop (from IP1, still the centre)

| Step | What the user does | Where |
|---|---|---|
| **Mark** | Sweep a controller across a surface holding grip → keep/change | `Runtime/MarkTool.cs` `OnTriggerStay` (41) → `Runtime/Surface.cs` `ToggleState` (94) |
| **Pull** | Trigger near a kept surface → sample in hand | `Runtime/SamplePuller.cs` `Update` (39), `SpawnFrom` (54). Refuses change surfaces: only kept things give samples |
| **Hold** | Bring the sample near a changeable wall → whole wall previews | `Runtime/HoldUpPreviewer.cs` `Update` (39): nearest change surface within `PreviewRadius` 0.45 m; leaving range reverts (57) |
| **Tune** | Twist the wrist → steps through 7 harmonised colours | `Runtime/HarmonyTuner.cs` `RollToIndex` (19), `Tick` (25) · colours from `Runtime/HarmonyPalette.cs` `Generate` (13): analogous, tonal, triadic, complementary |
| **Commit** | Release against the wall → applied; release mid-air → discarded | `Runtime/HoldUpPreviewer.cs` `OnReleased` (63): `Commit` (68) or `Destroy` (71) |
| **Surface state** | Keep/Change, committed vs previewed colour and material | `Runtime/Surface.cs` `Preview` (142), `Commit` (149), `PreviewMaterial` (159), `CommitMaterial` (166) |

## Desktop mode (editor only, for this test)

IP2a runs in the Unity editor with mouse and keyboard. None of this runs on a headset: the desktop scripts switch themselves off outside the editor (`Application.isEditor` / `#if UNITY_EDITOR`), and the Q/E path only runs while desktop mode is on.

| What | Where |
|---|---|
| Mouse aims the right-hand ray; right-drag looks (cursor locks); WASD walks, kept in the room | `Runtime/EditorDesktopRig.cs`: `TryCursorRay` (43), `Look` (57), `Walk` (62), `Update` |
| Click on lamp / clock / frame = touching it (hands can't reach a wall here) | **New** `Runtime/ITouchable.cs` · `Runtime/RayUtil.cs` `PickTouchable` · called from `EditorDesktopRig.Update` |
| Clicking those props doesn't also open the wall menu behind them | `Runtime/MenuSelectRelay.cs` `Update` (44) |
| Menu 0.45 m from the eye in desktop mode (0.8 m was unreadable) | `Runtime/EditorDesktopRig.cs` `MenuOffset` (32), applied in `Apply` (80) |
| W no longer aims a teleport; Q/E turn held furniture | `Runtime/EditorDesktopRig.cs` (`axis2DTargets` = None) · `TurnKeys` (54) · `Runtime/FurnitureInput.cs` |
| Hands ride the head so they're on screen | `Runtime/EditorGazeAim.cs` (`Compute` 66, `Converge` 76) |
| Keys reach the game even when another editor panel has focus | `Editor/ProjectConfigurator.cs` |

## If the professor asks…

| Question | Answer, and where to point |
|---|---|
| "How does the colour harmony work?" | `Runtime/HarmonyPalette.cs` `Generate` (13): from the sample's hue, 7 options ordered safe → bold (analogous, tonal, triadic, complementary). The wrist angle picks one: `Runtime/HarmonyTuner.cs` `RollToIndex` (19) |
| "How do you stop a preview sticking?" | `Runtime/HoldUpPreviewer.cs` 57: leaving range always calls `Revert`. Only a release inside range commits (68) |
| "Why is the scene generated?" | Repeatable and reviewable: one script rebuilds the room exactly, and the tests check what it produces. `Editor/SceneBuilder.cs` `Build` (29) |
| "How does grabbing furniture work?" | XRI `XRGrabInteractable`; on grab the piece keeps its offset from where the ray meets the floor, capped at 6 m reach. `Runtime/FurnitureSlot.cs` 137–199 |
| "How do you know it works?" | 169 EditMode + 27 PlayMode tests; PlayMode loads the real scene. E.g. `SceneWiringTests.Presets_Layout_NoOverlap_KeyPlacesClear_Spread` checks every room: nothing overlaps and the start spot, door and lamp are clear |
| "What about the headset?" | The same code runs on Quest: touch uses the controller's trigger collider (`OnTriggerEnter` in `PresetFrame`, `LampController`, `WallClock`). Desktop mode is editor-only. IP2b moves to the Quest in passthrough (MR) |
| "Where's the AI use?" | `ip2a/ai-use-log.md`: one row per change, what AI did and what I decided |
